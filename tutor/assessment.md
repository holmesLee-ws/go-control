# 성숙도 판정

## 수준

수준 척도는 go-develop과 같다(원래 ACM·IEEE-CS CS2023의 숙련 수준). 이 영역 전용 공인 척도가 없어 일관성을 택했다. Explain이 나머지의 선행 수준이다.

| 수준 | 이름 | 증거 |
|---|---|---|
| 0 | 미접촉 | 없음 |
| 1 | Explain | 자기 말로 설명하고, 왜 그런지 말한다 |
| 2 | Apply | 처음 보는 상황에서 직접 해내고, 결과를 예측한다 |
| 3 | Evaluate | 선택지를 비교해 근거와 함께 결정한다 |
| 4 | Develop | 실제 조직의 제약 안에서 쓸 수 있는 산출물(매트릭스·평가서·체계)을 만들어 낸다 |

## 증거의 무게

- 자기 신고는 어디부터 물어볼지 정하는 데만 쓴다. 숙달의 근거가 아니다.
- 탐침과 과제의 결과만 수준을 올린다.
- 정의나 조문 번호를 외워 답한 것은 증거가 아니다. 이 영역의 증거는 상황에 적용한 판단이다(예: 이 통제가 이 위험을 막는가, 이 미비점의 원인과 시정 책임자는 누구인가).

## 탐침 만드는 법

- 그 모듈의 목표 수준에 맞춘다. 정의를 묻지 않고 처음 보는 상황에서 예측·판단·진단하게 한다. 상황은 학습자 조직에 가까운 짧은 사례(가상의 회사·수치)로 만든다.
- 힌트를 주지 않고 짧게 답할 수 있게 낸다. 탐침은 예측·진단·수정 중 하나만 묻는다. 덧붙일 수 있는 것은 「이유」 하나뿐이다. 원인과 고치는 법은 다음 차례로 나눈다. 페이지 조작을 부탁한 차례에는 새 문제를 내지 않는다.
- 같은 모듈의 탐침 2개는 목표 문장의 서로 다른 요소를 다룬다. 정답 2개여도 목표 요소 중 아직 다루지 않은 것이 있으면 그 요소로 세 번째 탐침을 낸다.
- 판정 기준을 내기 전에 정한다. 결론만 맞고 이유가 틀리면 맞음이 아니다.

## 판정 절차

모듈당 탐침은 최대 3개, 판정까지 3차례를 넘기지 않는다. 3차례는 탐침을 낸 차례만 센다. 학습자의 사실·적용 질문에 답한 차례와 마지막 탐침의 답을 받아 판정을 알리는 차례는 세지 않는다. 목표 요소가 3개를 넘으면 한 탐침에 두 요소를 묶거나, 다루지 못한 요소를 `evidence`에 「미검증: ○○」로 적는다.

| 결과 | 경로 | 기록 |
|---|---|---|
| 낸 탐침이 모두 정답(2개 이상, 입구 진단에서 그 모듈을 직접 다룬 정답도 1개로 센다)이고 남은 목표 요소가 없거나 「미검증」으로 적었다 | 건너뜀. 한 줄로 알리고 다음으로 | `status: verified_skip`, 달성 수준, 증거 |
| 첫 탐침 오답이나 「모르겠어요」 | 한 단계 낮춰 다시 묻거나(Explain 모듈이면 풀이 예시로) 전체 경로로 | `status: in_progress` |
| 학습자가 그냥 넘어가겠다고 함 | 바로 넘어간다. 돌아올 수 있다고만 말한다 | `status: self_skip`, 증거 없음 |
| 정답·부분 정답·오답이 섞임 | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 학습자가 「처음 본다」고 함 | 탐침을 생략하고 풀이 예시부터 보여 준다 | `status: in_progress`, 시작 수준 0 |

- 「다 알아요」는 사실 진술이므로 강의하지 않고 곧바로 목표 수준 탐침을 낸다. 「건너뛰죠」는 결정이므로 바로 `self_skip`으로 넘어간다. 둘이 함께 나오면 결정을 따른다.
- 학습자가 시간을 쓰겠다고 말한 모듈은 탐침을 맞혀도 자동으로 건너뛰지 않고, 건너뛸지 더 깊이 볼지 묻는다.
- 목표가 Develop인 모듈(`curriculum/map.md`에서 목표가 Develop인 것)은 짧은 탐침으로 건너뛰지 않는다. 학습자가 이미 만든 결과물을 함께 검토해서만 건너뛴다. 결과물이 회사 자료면 기밀을 빼고 구조만 말해 달라고 한다.
- `self_skip`과 `estimated`는 숙달이 아니다. 선수 확인은 세션 흐름의 「모듈 하나의 흐름」 0단계를 따른다.
- 탐침에서 드러난 빈틈이 다른 모듈에 속하면 `gaps`에 기록하고, 지금 흐름에 필요한 만큼만 메운다.

## 영역 빠른 확인

학습자가 영역 전체를 빠르게 확인하고 싶어 하면, 뒤쪽의 심화 모듈부터 탐침한다. `verified_skip`이 된 모듈의 선수 모듈 중 **같은 영역**의 것(그 선수의 같은 영역 선수까지)만 `inferred`로 기록하고 다시 묻지 않는다. 다른 영역 선수는 `estimated`로 남기되 `level`을 비우고 `evidence`에 「○○ 통과로 추정」이라고 적는다. `done`·`verified_skip`·`self_skip`인 모듈은 바꾸지 않고, `estimated`인 같은 영역 선수는 `inferred`로 올린다. 다른 영역 `estimated`는 `verified_skip` 모듈의 직접 선수에만 적는다. 같은 영역 선수 사슬이 없는 심화 모듈은 따로 탐침한다(G 영역은 G2부터). 탐침 1개만 맞은 `estimated` 모듈로는 추론하지 않는다. 튜터도 입구 진단 뒤에 이 확인을 먼저 제안할 수 있다.

## 복습 간격

인출 연습과 분산 학습이 학습 기법 중 효용이 가장 높게 평가되었으므로(Dunlosky 외, 2013) 복습을 넣는다.

- 완료 시 `review_step: 0`, `review_at`은 1일 뒤로 둔다.
- 복습에 성공하면 간격을 3일, 7일, 21일로 늘린다. 21일 복습에도 성공하면 `review_at`을 `null`로 둔다.
- 실패하면 `review_step`을 0으로 돌리고 빈틈을 `gaps`에 적는다.
- 복습은 세션 시작 시 1개만 낸다. 새로운 상황으로 바꿔 묻는다.
- `verified_skip`은 복습 대상이 아니다.

## 기록 형식

`learner/state.json`의 `modules`에 모듈 id를 키로 둔다.

```json
"C2": {
  "level": 2,
  "status": "done",
  "evidence": ["2026-11-14 가상 회사 구매 프로세스 — 답: \"발주 넣는 사람이 대금 지급 승인까지 하면 안 되죠… 승인은 팀장\""],
  "review_at": "2026-11-15",
  "review_step": 0
}
```

`status`는 `estimated`, `inferred`, `in_progress`, `done`, `verified_skip`, `self_skip` 중 하나다. `inferred`는 상위 모듈을 통과해 추론한 것으로 다시 탐침하지 않는다.

출제와 채점을 튜터 혼자 하므로, `evidence`에는 판단만 적지 않고 **학습자의 답을 짧게 인용한다.** 따옴표 안은 대화에서 그대로 복사한다. 인용할 답에 실명·거래처·실제 금액이 있으면 그 부분을 `…`로 줄이고 따옴표 밖에 `(기밀 가림)`을 붙인다. 가명으로 바꿔 따옴표 안에 넣지 않는다. 구절을 잇거나 조사·어미를 바꾸지 않고, 줄일 때는 `…`를 쓴다. 바꿔 쓰려면 따옴표 밖 요약으로 쓴다.
